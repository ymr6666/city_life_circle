作品过程及成果截图说明清单

========================================================
第一部分：开发过程截图（证明"数据与算法全自研"）
========================================================

【图 1-1】数据库表结构总览
画面：pgAdmin 或 psql \dt 输出，显示 city_life_circle 库 18 张表清单。
描述语句：系统数据库采用 PostgreSQL + PostGIS + pgRouting，共设计 18 张业务表，
涵盖路网、设施、地铁、公交、人口及挂接关系，所有空间数据统一为 WGS84 坐标系。

【图 1-2】核心业务表数据量
画面：psql 对 hefei_roads / hefei_poi / hefei_pop_grid 等表执行 count(*) 的结果。
描述语句：核心数据规模：路网 104,132 条路段、42,785 个拓扑节点；设施 POI
21,243 条（21 类）；100 米人口格 169,877 点（约覆盖 623 万人）。

【图 1-3】路网与设施数据可视化
画面：在 GIS 软件或系统地图中叠加显示合肥路网与设施点位。
描述语句：基于 OpenStreetMap 采集的合肥真实路网与高德设施数据，在 GIS 中叠加
展示，并完成道路分级、桥隧分类与设施空间分布检查。

【图 1-4】公交/地铁数据入库
画面：psql 查询 hefei_bus_stops、hefei_bus_lines、hefei_metro_stations 结果。
描述语句：地铁系统含 169 座站点（20 个换乘站）、183 条轨道边；公交系统含
5,530 个站点、227 条线路、8,489 条有序站序，站点与线路均完成坐标匹配入库。

【图 1-5】路网拓扑与可达标志
画面：hefei_roads 表 walk_ok / cycle_ok / drive_ok 与 bridge_class 字段示例，
或 pgRouting 拓扑顶点可视化。
描述语句：对路网建立 pgRouting 拓扑，并按桥隧四档分类计算步行、骑行、驾车
三种模式的可达标志，为多模式路径计算奠定基础。

【图 1-6】POI 坐标转换与挂接
画面：脚本运行日志或 poi_road_nodes 挂接表示例（poi 到 node 的距离）。
描述语句：将高德 POI 由 GCJ-02 统一转换为 WGS84（保留备份表可回滚），并完成
设施到最近路网节点的挂接，共 119,368 条挂接记录，保证设施可达性判定准确。

【图 1-7】命令行可达性测试
画面：运行 python test_walk.py 的输出（可达节点/POI/地铁/公交数量）。
描述语句：开发阶段使用命令行工具对引擎进行逐点测试，验证多模式可达结果
（步行、地铁、公交及其组合）的正确性与性能。

【图 1-8】后端 API 接口测试
画面：浏览器或 Postman 调用 /api/isochrone 返回的 JSON 结果。
描述语句：后端提供正算、反算、评分、覆盖、规划等 13 组 REST 接口，以 JSON
返回 WGS84 坐标结果，前端通过接口驱动全部交互。

========================================================
第二部分：系统成果截图（按前端五个标签页）
========================================================

【图 2-1】生活圈分析——多模式等时圈
画面：首页地图上，同一地址步行与"步行+地铁"两种方式生成的等时圈。
描述语句：以指定地址为起点，系统沿真实路网扩散生成等时圈：步行圈贴合道路
走廊，叠加地铁后出现沿轨道交通延伸的可达走廊，直观体现多模式耦合可达性。

【图 2-2】生活圈分析——设施统计与覆盖人口
画面：左侧面板"设施统计"标签，显示圈内各分类设施数量与覆盖人口。
描述语句：系统统计等时圈内医院、学校、超市等各类设施数量与覆盖人口，
为个人生活配套评估提供量化依据。

【图 2-3】宜居评分卡
画面：评分标签页，显示五维子分、综合分、等级与权重滑块/家庭预设。
描述语句：宜居评分从医疗、教育、购物、休闲、交通五维计分，支持用户调节
权重与家庭结构（有老人/有小孩），结果附各维度依据明细，评分逻辑透明可解释。

【图 2-4】覆盖率-时间曲线
画面：覆盖率曲线图，横轴时间、双轴显示覆盖人口与覆盖设施。
描述语句：一次计算即可绘制覆盖率随时间衰减曲线，直观展示 5 至 30 分钟内
人口与设施覆盖的边际变化。

【图 2-5】反算选址——最优居住选址
画面：多个设施覆盖范围及其绿色交集区域。
描述语句：以设施为源反算覆盖范围，多个设施的覆盖交集即为同时可达全部设施的
最优居住选址区，直接支持"在哪里买房生活更方便"的决策。

【图 2-6】分级色彩——设施密度网格
画面：医院类别密度分级网格（红到绿），左下角图例。
描述语句：分级色彩页将研究范围划分为网格，以红到绿分级配色直观呈现单类设施
密度与综合宜居程度的空间差异，图例区间可自定义。

【图 2-7】人口分布——密度底图与区域统计
画面：人口密度瓦片底图叠加，框选区域后显示人口/面积/密度统计。
描述语句：系统内置 100 米分辨率人口密度底图，并支持框选或手绘多边形统计
区域人口、面积与密度，为覆盖与盲区分析提供需求侧基础。

【图 2-8】全城分析——服务盲区识别
画面：全城范围内红/黄/绿三级点状渲染（盲区/紧张/覆盖）及设施点。
描述语句：全城视角下，系统识别"15 分钟步行到不了任何医院"的盲区人口与空间
分布，绿色为已覆盖、红色为盲区，量化设施布局短板。

【图 2-9】全城分析——盲区聚类
画面：盲区底图点叠加连续盲区簇多边形与列表。
描述语句：系统将零散盲区聚合为连续盲区簇，给出每簇的盲区人口、中心与范围，
帮助规划人员定位最需要补设施的区域。

【图 2-10】全城分析——供需错配
画面：六边形错配图（红=缺口、绿=均衡、蓝=冗余）及弹窗明细。
描述语句：错配分析按网格统计人口与设施数量，以红蓝显示"高人口低设施"与
"低人口高设施"区域，识别供需失衡的典型片区。

【图 2-11】规划分析——选址模拟
画面：候选点标记、候选列表与"新建到第 N 座"累计覆盖对比图。
描述语句：选址模拟在指定范围内生成候选点，按"填补盲区人口"排序，并给出
逐座新建的累计覆盖与边际收益，为设施布点提供量化方案。

【图 2-12】规划分析——关闭/搬迁影响
画面：受影响/恢复/新增覆盖多边形与瀑布图（净变化）。
描述语句：系统量化设施关闭的受影响人口（区分完全失去与退级）、搬迁的恢复
人口与新增覆盖，并以瀑布图呈现净影响，辅助规划决策。

4. 可按"过程（1-1 至 1-8）→ 成果（2-1 至 2-12）"的顺序编排，形成
"数据采集—库表设计—引擎测试—前端功能"的完整逻辑链。
