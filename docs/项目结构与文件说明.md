## 二、backend/ —— 后端引擎与 API

### 启动与配置
- app.py —— Flask 入口，注册路由蓝图；python app.py 启动（localhost:5000）
- config.py —— 数据库连接、各出行速度参数（WALK/CYCLE/DRIVE/METRO/BUS_KMH）、合肥 bbox
- requirements.txt —— 依赖：flask、psycopg2-binary、requests
- test_walk.py —— 命令行测试工具：python test_walk.py [lat] [lng] [分钟] --mode xxx [gcj02] [--swap] [--radius N]

### engine/ —— 可达性引擎
- base_layer.py —— TransportLayer 抽象基类（吸附/可达/POI 接口）
- walk_layer.py —— 步行层：walk_ok 过滤、吸附、自适应半径、Dijkstra、POI 反查、等时圈 GeoJSON
- cycle_layer.py —— 骑行层：cycle_ok、15km/h、尊重单行道、排除 steps 与天桥
- drive_layer.py —— 驾车层：drive_ok、30km/h、单行道
- transit_layer.py —— 通用耦合引擎：道路+地铁+公交统一图单次 Dijkstra；节点偏移（路网 / 地铁100000+ / 公交200000+）；支持边方向反转（反算用）
- metro_layer.py —— 步行+地铁层（TransitLayer 子类）
- bus_layer.py —— 步行+公交层 / 步行+地铁+公交层
- factory.py —— build_layer(mode) 解析复合模式字符串（walk+metro+bus 等）
- reverse.py —— 反算引擎：设施→覆盖起点、多设施交集选址（边域多边形，非凸包）
- poi_stats.py —— 设施统计共享逻辑（category 聚合 + 同名近距去重，含 address 字段）
- scoring.py —— 五维宜居评分引擎（医疗/教育/购物/休闲/交通，typecode 加权 + 最近设施距离 + 优/良/中/差等级；交通维度与出行模式无关，统计起点周边 800m/400m 站）
- population.py —— 人口统计（hefei_pop_grid 100m 点表，多边形内人口/密度，150m 膨胀矫正）
- access_cache.py —— 等时圈结果 LRU 缓存（transit 重查询秒回）
- coord_utils.py —— WGS84 / GCJ-02 / BD-09 坐标互转

### routes/ —— HTTP API
- isochrone.py —— POST /api/isochrone（正算）+ POST /api/reverse-isochrone（反算）
- geocode.py —— GET/POST /api/geocode（地名/关键词 → WGS84 坐标，调高德搜索 POI 2.0）
- regeo.py —— GET/POST /api/regeo（WGS84 坐标 → 地址 + 最近 POI，高德逆地理编码）
- poi_stat.py —— POST /api/poi-stat（多边形内分类 POI 统计 + 地铁/公交站数，含 typecode 拆分与医院 canonical 去重）
- score.py —— POST /api/score（五维宜居评分：事实+用户权重+家庭结构 → 综合分+等级+子分）
- grid.py —— POST /api/grid（六边形网格分级统计，ST_HexagonGrid 纯空间统计，无 Dijkstra）
- roads.py —— GET /api/roads（视口路网 GeoJSON，随地图平移动态加载）
- tiles.py —— GET /tiles/pop/{z}/{x}/{y}.png（人口栅格预渲染瓦片，从 cache/pop_tiles 读取）

### services/
- database.py —— psycopg2 连接池 + execute_query / execute_one
- amap.py —— 高德 Web 服务客户端（/v5/place/text 搜索 POI 2.0）；GCJ-02→WGS84 边界转换；AMAP_KEY 解析（环境变量 → scripts/crawlers/config.py）

## 七、数据流总览

1. 数据采集
   高德 POI 爬虫 -> hefei_poi -> convert_poi_coords(GCJ转WGS) -> snap_poi_v2 -> poi_road_nodes
   OSM 地铁    -> hefei_metro_* -> snap_metro_stations -> metro_station_road_nodes
   官方平台+8684 -> hefei_bus_* -> snap_bus_stops -> bus_stop_road_nodes
   osmnx 路网  -> rebuild_topo -> enrich_roads_tags(桥隧分类) -> hefei_roads(+分类列)

2. 引擎
   factory.build_layer(mode) -> TransitLayer/WalkLayer/CycleLayer/DriveLayer
   -> pgr_drivingDistance(统一图) -> 可达节点/地铁/公交 -> POI 反查

3. API
   /api/isochrone（正算） /api/reverse-isochrone（反算） -> JSON（WGS84）

4. 前端（Vue3 + Leaflet，待开发）
   调 isochrone 画等时圈 + 设施；调 reverse 画覆盖区/选址

## 八、数据库表结构与示例数据（共 14 张表）

> 数据库：city_life_circle（PostgreSQL 13 + PostGIS 3.6 + pgRouting 4.0.1）
> 14 张表 = 8 核心业务 + 3 挂接 + 3 派生/辅助（hefei_nodes 原始节点、road_node_modes 顶点模式缓存、hefei_poi_gcj_backup 坐标备份）。

### 8.1 核心业务表

#### hefei_roads（104,132 行）核心路网
列：u, v, osmid（OSM 边），highway（道路等级），lanes, name, oneway, ref, reversed,
length（米）, maxspeed, bridge, tunnel, access, service, width, junction, landuse,
id（自增主键）, source, target（pgRouting 拓扑节点）, cost, reverse_cost（米）,
layer, foot, bicycle, motor_vehicle, vehicle, sidewalk, cycleway, surface,
smoothness, lit, segregated, oneway_bicycle, incline（enrich_roads_tags 补的 OSM tag）,
bridge_class（桥隧四档：none/bridge/elevated/tunnel/footbridge）,
walk_ok / cycle_ok / drive_ok（布尔可达标志）

示例：
- id=24581  highway=secondary  name=NULL  bridge_class=NULL  walk_ok=True  drive_ok=True  cost=460.1m
- id=24623  highway=secondary  name=白店路  bridge_class=NULL  walk_ok=True  drive_ok=True  cost=2094.5m

#### hefei_roads_vertices_pgr（42,785 行）拓扑顶点
列：id（自增主键）, osm_id, x, y, geometry(Point)
注意：x=纬度，y=经度（rebuild_topo 的 y AS x, x AS y 所致，代码输出时用 v.y AS lng, v.x AS lat）

示例：
- id=1  osm_id=251189246  x(纬度)=31.8042  y(经度)=117.3316
- id=2  osm_id=251191215  x(纬度)=31.8094  y(经度)=117.1915

#### hefei_nodes（42,785 行）原始 OSM 节点（osmnx 导入，未参与分析）
列：osmid, x, y, highway, ref, street_count, railway, geometry

#### hefei_poi（6,567 行）设施 POI（WGS84）
列：id（自增主键）, name, category（12 类）, sub_category（高德 typecode）,
address, tel, business_area, rating, cost, parking_type,
opentime_today, opentime_week, tag, alias,
entr_location / exit_location（导航入口坐标"lng,lat"，已转 WGS84）,
navi_poiid, photos, geometry(Point), canonical_poi_id（多楼栋医院分组代表）

示例：
- id=6622  name=肥西经开区华南城门诊部  category=hospital  sub_category=090300  entr_location=117.103876,31.764750
- id=6623  name=乐雅口腔(肥西院)        category=hospital  sub_category=090202  entr_location=117.099714,31.767540

#### hefei_metro_stations（169 行）地铁站
列：id, name, line_name（如 "1|2" 表示换乘）, is_transfer, sequence, geometry(Point)

示例：id=191 name=兴华苑 line_name=1 is_transfer=False；id=192 name=瑶海公园 line_name=1 is_transfer=False

#### hefei_metro_edges（183 行）地铁轨道边
列：id, line_name, station_from, station_to, distance_km, time_min, geometry(LineString)

示例：line=1 station_from=191 station_to=192 距离=1.478km 时间=2.53min

#### hefei_bus_stops（5,530 行）公交站（WGS84）
列：id（官方 STATIONID 文本）, stop_no（自增，图节点整数号）, name, adcode, lng, lat, geometry(Point)

示例：id=1003 stop_no=1 name=翠竹园 lng=117.25166 lat=31.872738

#### hefei_bus_lines（227 行）公交线路
列：id（线路码，如 46）, name, type（等级）, start_stop, end_stop, distance_km, company, geometry

示例：id=123 name=合肥123路 start_stop=静安新城 end_stop=小花园 distance_km=8.8；id=46 name=合肥46路 公交双墩站->市府广场西

#### hefei_bus_line_stops（8,489 行）公交线路有序站点
列：line_id, stop_id, direction(up/down), sequence, route_pos_m（沿程里程）
主键：(line_id, stop_id, direction)

示例：T38 up: stop=4366 seq=0 pos=0m -> stop=3544 seq=1 pos=1388.9m -> stop=3545 seq=2 pos=2793.7m

### 8.2 挂接表（站点/POI 到路网节点，0 成本换乘边用）

#### poi_road_nodes（25,351 行）POI 挂接
列：id, poi_id, node_id, mode（walk/drive）, distance_m

示例：poi_id=6622 挂到 node=36829 mode=walk 距离=113.6m

#### metro_station_road_nodes（436 行）地铁站挂接
列：id, station_id, node_id, distance_m

示例：station=191 挂到 node=16499 距离=255.5m

#### bus_stop_road_nodes（14,013 行）公交站挂接
列：id, stop_no, node_id, distance_m

示例：stop_no=1 挂到 node=3025 距离=150.3m

### 8.3 派生 / 辅助表

#### road_node_modes（116,088 行）顶点可达模式缓存
列：node_id, mode（walk 等）
作用：吸附时快速判断顶点属于哪种模式网络。

#### hefei_poi_gcj_backup（6,567 行）POI 原始坐标备份
列：id, geometry, entr_location, exit_location
作用：convert_poi_coords.py 转换前备份，出错可回滚。

## 九、为什么是 14 张表（结构演进）

初始只有 4 张核心（roads/vertices/poi/metro）。
随后为支持多模式 + 公交逐步增加：
- +2 挂接表（poi_road_nodes, metro_station_road_nodes）
- +3 公交表（hefei_bus_stops/lines/line_stops）+ 公交挂接 bus_stop_road_nodes
- +1 坐标备份（hefei_poi_gcj_backup）
- +1 顶点模式缓存（road_node_modes）
- hefei_nodes 是 osmnx 导入的原始表（分析不直接用）
