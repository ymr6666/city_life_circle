# 前端开发对接说明（给前端同学）

> 项目：城市时域生活圈分析系统
> 一句话：输入一个坐标 → 选择出行方式和时间 → 算出"能到哪"（等时圈）→ 圈内有哪些设施 → 宜居评分。
> **2026-08-08 更新**：前端已改为 Vue3 + Vite + Leaflet 工程（`frontend/`），含三个 Tab：
> 「生活圈分析」（定位/多点分析/等时圈/反算/统计/评分）、「分级色彩」（六边形网格 choropleth）与
> 「人口分布」（**100m 人口栅格预渲染瓦片底图**，任意缩放无需重新计算）。
> 新增 API：`/api/regeo`（逆地理编码）、`/tiles/pop/{z}/{x}/{y}.png`（人口栅格瓦片）、
> `/api/score`（五维宜居评分+等级）、`/api/grid`（六边形网格分级统计）。

---

## 一、技术栈与架构

```
前端 (Vue 3)  --HTTP-->  后端 Flask (localhost:5000)  --SQL-->  PostgreSQL + PostGIS + pgRouting
```

- **前端建议**：Vue 3 + **Leaflet** + turf.js（画圈用）。见"四、坐标系"为什么建议 Leaflet。
- **后端**：已实现好并连好本地数据库，**你只需要调 HTTP API，不需要装/连数据库**。

## 二、先把后端跑起来

```bash
cd backend
pip install -r requirements.txt   # flask, psycopg2-binary, requests
python app.py                     # 监听 http://localhost:5000
```

后端启动后，所有接口在 `http://localhost:5000/api/...`。

## 三、API 契约

### 3.1 正算：`POST /api/isochrone`

**请求**（JSON body）：
```json
{
  "lat": 31.861,
  "lng": 117.285,
  "mode": "walk+metro+bus",
  "time_budget_min": 30,
  "snap_radius_m": 150
}
```

**`mode` 可选值**：
| 值 | 含义 |
|----|------|
| `walk` / `cycle` / `drive` | 步行 / 骑行 / 驾车 |
| `metro` | = walk+metro（别名） |
| `bus` | = walk+bus（别名） |
| `walk+metro` / `walk+bus` / `walk+metro+bus` | 步行接驳 + 公交 |

**响应**（JSON）：
```
mode                    string  请求的模式
time_budget_min         number
origin                  {lat, lng}
start_node              {id, lng, lat, distance_m}   起点吸附到的路网节点（distance_m=起点到路网的距离）
snap_radius_m           number   实际吸附半径（稀疏区域会自动放大 150→300→500→800）
reachable_pois_count    number
reachable_population    number   圈内覆盖人口 (100m 人口栅格, 多边形外扩150m矫正)
population_density_per_km2 number 圈内人口密度
pois_by_category        { "hospital": {count, items:[{id,name,address,sub_category,lng,lat,distance_m}]}, ... }
                        // 原始 POI 粒度（同一医院的科室/楼宇各自列出，引擎视角）
facilities_by_category  { "hospital": {count, items:[{name,address, sub_category, lng, lat, count, items}]}, ... }
                        // 设施粒度（facility_id 去重 + 同名近距合并；展示/卡片推荐用；count=可达子POI数）
reachable_facilities_count  number   设施去重后的总数

-- 单模式 (walk/cycle/drive) 时：
distance_budget_m       number   距离预算(米)
reachable_nodes_count   number
reachable_nodes         [{node, agg_cost, lng, lat}]   可达路网节点（agg_cost=到起点距离/时间成本）

-- 耦合模式 (含 metro/bus) 时：
reachable_road_nodes_count / reachable_road_nodes   [{node, agg_cost, lng, lat}]
reachable_metro_stations_count / reachable_metro_stations  [{id,name,line_name,is_transfer,time_min,lng,lat}]
reachable_bus_stops_count / reachable_bus_stops      [{id,name,time_min,lng,lat}]
```

### 3.2 反算：`POST /api/reverse-isochrone`

**请求**：
```json
{
  "facilities": [{"lat":31.861,"lng":117.285}, {"lat":31.855,"lng":117.275}],
  "mode": "walk",
  "time_budget_min": 15,
  "snap_radius_m": 150
}
```
语义：找出"能在 T 分钟内到达这些设施"的起点区域；≥2 个设施时返回交集 = 最优选址区。

**响应**：
```
mode, time_budget_min
facilities: [
  {lat, lng, snap_ok, snap_candidates,
   reachable_origins_count, reachable_origins: [{node, agg_cost, lng, lat}],
   reachable_population: number,   // 该设施覆盖范围人口
   polygon: <GeoJSON Polygon>}    // 该设施覆盖范围
]
intersection: {                   // 仅当 facilities >= 2
  facilities_count, reachable_origins_count, reachable_origins,
  reachable_population: number,   // 交集(最优选址区)覆盖人口 —— 人口加权选址依据
  polygon
}
```

### 3.3 地理编码：`GET /api/geocode`

把**地名 / 地址关键词**变成坐标（前端搜索框入口），再拿去调 `/api/isochrone`。

**请求**（GET query 或 POST JSON 均可）：
```
GET /api/geocode?keywords=政务区万象城&region=合肥&limit=5[&types=060100]
POST /api/geocode  {"keywords": "政务区万象城", "region": "合肥", "limit": 5, "types": null}
```

**响应**（JSON）：
```
query        string    查询关键词
region       string    限定城市（默认合肥）
coord_sys    string    "WGS84"（所有坐标均为 WGS84，lng 在前）
count        number
results: [   // 高德搜索 POI 2.0，按相关度排序，最多 limit 条
  {name, address, typecode, type, adcode, city, district, lng, lat}
]
```

- `lng`/`lat` 为 **WGS84**，可直接填入 `/api/isochrone` 的 lat/lng。
- 数据源为高德搜索 POI 2.0（`/v5/place/text`），高德返回 GCJ-02，后端在接口边界**一次性**转成 WGS84；`coord_sys` 字段即声明此约定。
- 无匹配时返回 `404` 与空 `results`。

### 3.4 逆地理编码：`GET /api/regeo`

把 WGS84 坐标 → 格式化地址 + 最近 POI。用于地图选点、反算设施列表显示地址（而非裸经纬度）。

**请求**：
```
GET /api/regeo?lat=31.861&lng=117.285[&poinums=3]
POST /api/regeo  {"lat":31.861,"lng":117.285}
```

**响应**（JSON）：
```
lng, lat        number    (回显)
address         string    格式化地址, 如 "安徽省合肥市庐阳区逍遥津街道庐江路6号..."
province/city/district/township
poi             {name, address, type, distance_m, lng, lat} | null   最近 POI
```
- 数据源为高德 /v3/geocode/regeo，坐标在接口边界 WGS84→GCJ-02 转换。
- 逆地理编码消耗高德配额，前端应按点缓存。

### 3.5 多边形内分类统计：`POST /api/poi-stat`

对**任意多边形**（如前端用 turf 对等时圈节点做的 concave hull、多圈并集、或用户自画区域）做分类设施统计，也是评分接口的数据来源。

**请求**（JSON body）：
```json
{
  "polygon": { "type": "Polygon", "coordinates": [[[lng,lat],...]] },
  "include_items": false
}
```
- `polygon`：GeoJSON Polygon / MultiPolygon / Feature（坐标 **WGS84**，lng 在前）。
- `include_items`：true 时每个分类附带设施点列表（每类最多 200 条）。

**响应**（JSON）：
```
total_pois           number        圈内 POI 总数（原始粒度）
total_facilities     number        圈内设施总数（facility_id 去重）
pois_by_category     { "hospital": { count, sub_categories: {"090101": 3, ...}, [items] }, ... }
                     // sub_categories 为高德 typecode 拆分计数（组合码如 "090601|090300" 逐项计入）
facilities_by_category { "hospital": { count, items:[{name, sub_category, lng, lat, count}] } }
                     // 设施粒度，评分/展示用（三甲数量等按设施计）
metro_stations       number        圈内地铁站数
bus_stops            number        圈内公交站数
```

### 3.6 宜居评分：`POST /api/score`

等时圈内五维宜居评分（医疗/教育/购物/休闲/交通），三层透明：事实 → 权重 → 等级。
**2026-08-08 改版**：去掉人口密度"居住"维度（改为展示覆盖人口）；交通维度改为统计
"起点步行可达 800m/400m 内的地铁/公交站"（与出行模式无关，各模式评分可横向比较）；
综合分换算为 优/良/中/差 等级。

**请求**（JSON body）：
```json
{
  "lat": 31.861, "lng": 117.285,
  "mode": "walk", "time_budget_min": 15,
  "weights": {"medical": 1.4, "education": 1.5},   // 可选, 用户维度权重 (默认全 1)
  "family": "none"                                   // 可选: none/elderly/child/elderly+child
}
```

**响应**（JSON）：
```
score               number     综合宜居分 0-100
grade               string     等级: 优(≥85) / 良(≥70) / 中(≥55) / 差
grade_desc          string     等级描述
area_km2            number     等时圈面积(km²)
reachable_pois_count number
reachable_facilities_count number 设施去重数
population          number     圈内覆盖人口
population_density_per_km2 number
sub_scores          { "medical": {score, label, cap, facts:{weighted_count, nearest_distance_m, nearest_category, categories}}, ... }
                    // 五维子分 + 依据明细 (weighted_count=typecode加权数, nearest=最近设施直线距离;
                    //  transit 的 categories 为附近地铁/公交站数, 与模式无关)
weight_info         { user_weights, family }
```

### 3.7 六边形网格分级：`POST /api/grid`

对给定 bbox 切六边形网格，统计每格分类设施/地铁/公交数，计算综合评分或密度（纯空间统计，无路网计算，秒级）。

**请求**（JSON body）：
```json
{
  "bbox": [117.20, 31.75, 117.40, 31.95],
  "cell_size_deg": 0.01,        // 六边形大小 (度, 0.01 ≈ 1km)
  "metric": "score",            // score=综合评分 | population=人口密度 | density=设施密度
  "category": "supermarket"     // metric=density 时可指定单类
}
```

**响应**：GeoJSON FeatureCollection，每 feature `properties` 含：
```
score      number   综合评分 0-100 (或密度换算分)
counts     {category: n, ...}
population number   格内人口 (100m 人口栅格)
metro, bus number    格内地铁站/公交站数
area_km2   number
```

### 3.8 人口栅格瓦片：`GET /tiles/pop/{z}/{x}/{y}.png`

100m 人口栅格（PopSE China 2020）重投影到 Web Mercator 后预切 XYZ 瓦片（z9-14，
合肥范围），前端作为**底图叠加图层**使用——任何缩放级别直接可用，无需重新计算。

- 生成：`scripts/utils/build_pop_tiles.py`（rasterio，产物在 `cache/pop_tiles/`）
- 色阶：黄 → 橙 → 红（每 90m 格人口 0~500+），0 值透明
- 前端：`L.tileLayer('/tiles/pop/{z}/{x}/{y}.png', {bounds: 合肥, maxNativeZoom: 14})`

## 四、坐标系（务必注意，踩坑重灾区）

- **所有接口返回的坐标均为 WGS84**（`lng` 在前，`lat` 在后，数值上 lng≈117.x, lat≈31.x）。
- ✅ **用 Leaflet + OSM/天地图**：直接 `L.marker([lat, lng])`，无需转换。
- ❌ **若用高德 / 百度地图 JS SDK**：它们用 GCJ-02 / BD-09，直接用 WGS84 会**偏移约 570m**（所有点偏到别处）。要用就必须先转坐标，强烈建议改用 Leaflet。
- POI、地铁站、公交站的坐标也都是 WGS84，已统一。

## 五、等时圈（"能到哪"的面）怎么画

后端已直接返回 `polygon`（GeoJSON，道路走廊重建，已包含可达 POI 点位），前端直接用即可。
- 单模式（walk/cycle/drive）：多边形为可达路段 buffer，较丰满；
- 多模式（地铁/公交）：保留中心区 + 走廊/孤岛的 MultiPolygon 形状；
- 反算覆盖/交集也为道路走廊形状（非凸包），体现不同交通方式的形状差异。

## 六、页面结构（已实现）

1. **顶栏**：三个 Tab —— 生活圈分析 / 分级色彩 / 人口分布
2. **生活圈分析**（左栏输入 + 右栏操作/结果分离）：
   - 「定位」：搜索 + 地图选点（容器级捕获）+ 地址显示 + **分析点列表**（多点多色）
   - 「出行」：**出行方式多选**（步行/骑行/驾车/地铁/公交/公交+地铁 可勾选多个）+ 时间滑块 +
     「生成生活圈」——一次生成多种方式的可达范围，用**不同颜色范围线**同图显示
   - 右栏三个 Tab，**操作与结果同屏**（不再左右来回看）：
     - 设施统计：模式切换 chip + 分类设施统计
     - 宜居评分：权重滑块 + 家庭 + 评分按钮 + 评分卡（含等级与依据）
     - 反算选址：设施清单（可地图选点）+ 计算按钮 + 结果
   - ≥2 个点有结果时，底部出现**多地点对比表**
3. **分级色彩**：当前视野六边形网格综合评分/设施密度 choropleth（人口已改为栅格底图）
4. **人口分布**：**100m 人口栅格预渲染瓦片底图**（黄→橙→红，叠加在任意底图上，缩放无需重新计算）
