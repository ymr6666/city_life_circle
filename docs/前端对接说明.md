# 前端开发对接说明（给前端同学）

> 项目：城市时域生活圈分析系统
> 一句话：输入一个坐标 → 选择出行方式和时间 → 算出"能到哪"（等时圈）→ 圈内有哪些设施 → （未来）宜居评分。

---

## 一、技术栈与架构

```
前端 (Vue 3)  --HTTP-->  后端 Flask (localhost:5000)  --SQL-->  PostgreSQL + PostGIS + pgRouting
```

- **前端建议**：Vue 3 + **Leaflet** + turf.js（画圈用）。见"四、坐标系"为什么建议 Leaflet。
- **后端**：已实现好并连好本地数据库，**你只需要调 HTTP API，不需要装/连数据库**。

## 二、先把后端跑起来

```bash
cd backend
pip install -r requirements.txt   # flask, psycopg2-binary, requests
python app.py                     # 监听 http://localhost:5000
```

后端启动后，所有接口在 `http://localhost:5000/api/...`。

## 三、API 契约

### 3.1 正算：`POST /api/isochrone`

**请求**（JSON body）：
```json
{
  "lat": 31.861,
  "lng": 117.285,
  "mode": "walk+metro+bus",
  "time_budget_min": 30,
  "snap_radius_m": 150
}
```

**`mode` 可选值**：
| 值 | 含义 |
|----|------|
| `walk` / `cycle` / `drive` | 步行 / 骑行 / 驾车 |
| `metro` | = walk+metro（别名） |
| `bus` | = walk+bus（别名） |
| `walk+metro` / `walk+bus` / `walk+metro+bus` | 步行接驳 + 公交 |

**响应**（JSON）：
```
mode                    string  请求的模式
time_budget_min         number
origin                  {lat, lng}
start_node              {id, lng, lat, distance_m}   起点吸附到的路网节点（distance_m=起点到路网的距离）
snap_radius_m           number   实际吸附半径（稀疏区域会自动放大 150→300→500→800）
reachable_pois_count    number
pois_by_category        { "hospital": {count, items:[{id,name,sub_category,lng,lat,distance_m}]}, ... }
                        // 原始 POI 粒度（同一医院的科室/楼宇各自列出，引擎视角）
facilities_by_category  { "hospital": {count, items:[{name, sub_category, lng, lat, count, items}]}, ... }
                        // 设施粒度（facility_id 去重，展示/卡片推荐用；count=可达子POI数）
reachable_facilities_count  number   设施去重后的总数

-- 单模式 (walk/cycle/drive) 时：
distance_budget_m       number   距离预算(米)
reachable_nodes_count   number
reachable_nodes         [{node, agg_cost, lng, lat}]   可达路网节点（agg_cost=到起点距离/时间成本）

-- 耦合模式 (含 metro/bus) 时：
reachable_road_nodes_count / reachable_road_nodes   [{node, agg_cost, lng, lat}]
reachable_metro_stations_count / reachable_metro_stations  [{id,name,line_name,is_transfer,time_min,lng,lat}]
reachable_bus_stops_count / reachable_bus_stops      [{id,name,time_min,lng,lat}]
```

### 3.2 反算：`POST /api/reverse-isochrone`

**请求**：
```json
{
  "facilities": [{"lat":31.861,"lng":117.285}, {"lat":31.855,"lng":117.275}],
  "mode": "walk",
  "time_budget_min": 15,
  "snap_radius_m": 150
}
```
语义：找出"能在 T 分钟内到达这些设施"的起点区域；≥2 个设施时返回交集 = 最优选址区。

**响应**：
```
mode, time_budget_min
facilities: [
  {lat, lng, snap_ok, snap_candidates, 
   reachable_origins_count, reachable_origins: [{node, agg_cost, lng, lat}],
   polygon: <GeoJSON Polygon>}    // 该设施覆盖范围
]
intersection: {                   // 仅当 facilities >= 2
  facilities_count, reachable_origins_count, reachable_origins, polygon
}
```

### 3.3 地理编码：`GET /api/geocode`

把**地名 / 地址关键词**变成坐标（前端搜索框入口），再拿去调 `/api/isochrone`。

**请求**（GET query 或 POST JSON 均可）：
```
GET /api/geocode?keywords=政务区万象城&region=合肥&limit=5[&types=060100]
POST /api/geocode  {"keywords": "政务区万象城", "region": "合肥", "limit": 5, "types": null}
```

**响应**（JSON）：
```
query        string    查询关键词
region       string    限定城市（默认合肥）
coord_sys    string    "WGS84"（所有坐标均为 WGS84，lng 在前）
count        number
results: [   // 高德搜索 POI 2.0，按相关度排序，最多 limit 条
  {name, address, typecode, type, adcode, city, district, lng, lat}
]
```

- `lng`/`lat` 为 **WGS84**，可直接填入 `/api/isochrone` 的 lat/lng。
- 数据源为高德搜索 POI 2.0（`/v5/place/text`），高德返回 GCJ-02，后端在接口边界**一次性**转成 WGS84；`coord_sys` 字段即声明此约定。
- 无匹配时返回 `404` 与空 `results`。

### 3.4 多边形内分类统计：`POST /api/poi-stat`

对**任意多边形**（如前端用 turf 对等时圈节点做的 concave hull、多圈并集、或用户自画区域）做分类设施统计，也是评分接口的数据来源。

**请求**（JSON body）：
```json
{
  "polygon": { "type": "Polygon", "coordinates": [[[lng,lat],...]] },
  "include_items": false
}
```
- `polygon`：GeoJSON Polygon / MultiPolygon / Feature（坐标 **WGS84**，lng 在前）。
- `include_items`：true 时每个分类附带设施点列表（每类最多 200 条）。

**响应**（JSON）：
```
total_pois           number        圈内 POI 总数（原始粒度）
total_facilities     number        圈内设施总数（facility_id 去重）
pois_by_category     { "hospital": { count, sub_categories: {"090101": 3, ...}, [items] }, ... }
                     // sub_categories 为高德 typecode 拆分计数（组合码如 "090601|090300" 逐项计入）
facilities_by_category { "hospital": { count, items:[{name, sub_category, lng, lat, count}] } }
                     // 设施粒度，评分/展示用（三甲数量等按设施计）
metro_stations       number        圈内地铁站数
bus_stops            number        圈内公交站数
```

## 四、坐标系（务必注意，踩坑重灾区）

- **所有接口返回的坐标均为 WGS84**（`lng` 在前，`lat` 在后，数值上 lng≈117.x, lat≈31.x）。
- ✅ **用 Leaflet + OSM/天地图**：直接 `L.marker([lat, lng])`，无需转换。
- ❌ **若用高德 / 百度地图 JS SDK**：它们用 GCJ-02 / BD-09，直接用 WGS84 会**偏移约 570m**（所有点偏到别处）。要用就必须先转坐标，强烈建议改用 Leaflet。
- POI、地铁站、公交站的坐标也都是 WGS84，已统一。

## 五、等时圈（"能到哪"的面）怎么画

接口返回的是**可达路网节点**（点云），不是现成的面。两种画法：
1. **点云**：直接把 `reachable_nodes`（或 `reachable_road_nodes`）的 lng/lat 画成小点，最精确。
2. **面**：用 turf.js 对节点做 `turf.concave(points, {maxEdge: 800})` 或粗略的 `turf.convex()`。
   - 注意：多模式（地铁/公交）覆盖范围大，凸包会填满整个区域，**建议用 concave**。
- 反算接口已直接返回 `polygon`（GeoJSON），可直接画。

## 六、建议的页面结构（MVP 闭环）

1. **地图**（Leaflet）+ 点击取点 / 坐标输入框
2. **控制区**：出行模式下拉（walk/cycle/drive/walk+metro/walk+bus/walk+metro+bus）+ 时间滑块（5~60min）+ "生成"按钮
3. **图层**：
   - 等时圈（节点点云或 concave 面）
   - 可达设施点（`pois_by_category` 按类别分色）
   - 可达地铁站/公交站（耦合模式时）
4. **统计面板**：各设施类别数量卡片（`pois_by_category`）
5. （后续）评分卡、多圈对比、反算选址
